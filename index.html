Selected work

Interlock

2026–ongoing

A runtime firewall that stops AI agents from exfiltrating secrets. A Go MCP proxy tracks sensitive values through base64, hex, URL and gzip encodings and refuses to forward exfiltrating tool calls; eBPF traces connect() and write() underneath to catch the side channels the proxy cannot see. Containment defers roughly 100ms after a trip: a deliberate tradeoff, proof over speed, so a payload receipt exists before SIGKILL fires.

Enforces

  • Encoding-aware value tracking across base64, hex, URL-encoding, reversal and gzip, including depth-2 nests and secrets split across calls via a session fragment buffer
  • Syscall-level egress detection via cilium-ebpf, correlating connect(), sendto() and write() by PID, with a tunable payload capture window (payload_capture_bytes, default 512)
  • Sensor-only Kubernetes DaemonSet with PID-to-pod attribution, validated on EKS (AL2023/containerd); a Unix-socket taint bridge from the proxy lets the least-privilege capabilities posture reach EXFIL verdicts without privileged /proc reads
  • Prometheus metrics, OCSF SIEM export, Slack and PagerDuty trip webhooks
  • 178 tests, including known-gap tests that assert what each detector misses; ~0.5ms overhead engine-on versus passthrough on sensitive reads (a local benchmark, not a production SLO)

Known gaps

  • Semantic or paraphrased exfiltration is out of scope for the EXFIL verdict: a secret described in natural language, carrying no registered byte form, will not be proven. Value overlap also stops at depth-4 nests and compressors other than gzip
  • eBPF contains by killing after a correlated connect() and write(), not before the first packet; in-kernel blocking via LSM/KRSI is not shipped. IPv6, sendmsg and writev are untraced, and DoH/DoT is explicitly out of scope

Zenith

2025–2026

A Zanzibar-inspired authorization engine answering "does subject S have relation R on object O" over a relation-tuple graph, with recursive userset expansion and cycle detection. Built to understand the tradeoffs from the implementer's side rather than the consumer's.

Enforces

  • Recursive relation-tuple expansion (Zanzibar-style) with cycle detection over a DAG of usersets
  • Zookie-based causal consistency using CockroachDB logical timestamps
  • Singleflight deduplication and an LRU cache with selective, not full-flush, invalidation on writes
  • Reverse expansion (list all subjects with a relation) alongside forward checks
  • Direct checks run in low single-digit microseconds on the hot path in Go benchmarks (~1.2μs/op); sub-10ms end-to-end is the target, not yet measured against production traffic

Go · CockroachDB · gRPC · Prometheus

Arbor

2026

A SQL query engine over Apache Arrow and Parquet, written from scratch: parser, logical planner, rule-based optimizer, and a pull-based Volcano executor. No DataFusion or Polars in the execution path: the point was owning the whole planner-to-executor route.

Enforces

  • Predicate pushdown, projection pruning, constant folding
  • Inner joins over equi predicates, GROUP BY aggregates, ORDER BY/LIMIT
  • Module boundaries checked in CI: the parser cannot reach storage, the planner cannot reach Parquet I/O, the executor cannot reach the AST
  • No unwrap in library code; clippy and rustdoc both run with warnings denied
  • The optimizer is worth 3.2x on a synthetic TPC-H-style Q6 at ~900k rows, measured with Criterion as optimizer-on versus optimizer-off on the same engine (not a comparison to any other system)

Known gaps

  • SELECT only. No subqueries, HAVING, DISTINCT, set operations, or outer joins at execution
  • Rule-based optimizer: there is no cost model

Rust · Apache Arrow · Apache Parquet

Dispatch

2026

A multi-tenant webhook delivery platform. The interesting bug was a probe-stampede race in the half-open circuit breaker: concurrent recovery probes could all fire on a dead endpoint at once. Fixed with a conditional UPDATE, single-flighted via ClaimProbe, that lets exactly one signed event probe a recovering endpoint.

Enforces

  • Single Kafka retry topic with retry_after; exhausted events land in a Postgres DLQ, chosen over a Kafka topic so replay gets filtering and pagination
  • tenant_id kept off ingest metric labels to protect Prometheus cardinality
  • REST and gRPC ingest share one internal service path; HMAC-signed delivery with retries and dead-letter replay
  • ~50 events/sec sustained ingest (750 requests, 100% 202), delivery p99 ~2.5ms with 99.7% of deliveries under 2.5ms (measured on local Docker Compose under vegeta, not a cloud deployment)

Go · PostgreSQL · Kafka · Redis
